# api の残り (S2・S3・S4・S6 と見る側の画像) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 仮の api に残っている口を本物にする。登録 (S2)、見る側の画像・ブロック・通報・Web デモの模擬の検出、照合 (S3)、着用イメージ (S4)、AI を止める切り替え (S6)。

**Architecture:** `server/api/` に口ごとの router を足し、`main.py` で仮の口より先に登録する (既存の routes_me・broadcast・nearby と同じ形)。Storage は `blobs.py` を通し、テストでは辞書の偽物に替える。Gemini は関数 1 つを通し、テストでは偽物に替える。

**Tech Stack:** FastAPI、google-cloud-firestore (エミュレータで試す)、google-cloud-storage、google-genai (Agent Platform、`global`)、Pillow

**Spec:** `docs/api.yaml` (正本)、`docs/architecture.md` の 3.3〜3.5・4・5 節

## Global Constraints

- モデル名は `gemini-3.8-flash` (照合)、`gemini-nano-banana-2.1` (着用イメージ)。替えない
- 見る側に返すのは cardId と cardItemId だけ。uid・手持ちの id・匿名 ID・Storage の URL を他人に返さない。他人の画像は api が透かし入りのバイトで返す
- 着用イメージは本人にだけ返す。自分の写真は `capturedWith=camera` の物だけ受ける
- ログに ID トークン・匿名 ID・素の uid を書かない (例外の型の名前だけ)
- 回数の上限は `auth.charge(db, uid, kind, date)`。種類は `match` (30)、`tryon` (10)
- エラーは `HTTPException(status, {"code", "message"})` (main.py がエラーの形にする)。code は api.yaml の Error の enum から
- 改行は LF。テストは `server/api` で `pytest -q` (エミュレータを先に立てる)

## 共有する決まり (Task 1 で作る。Task 2 と 3 はこれを使う)

- `users/{uid}/wardrobeItems/{itemId}`: Garment の項目 (`slot` `category` `label` `layer` `color` `pattern` `materialGuess`) + `image` (Storage の path) + `memo` + `createdAt` (aware datetime) + `jobId`
- `users/{uid}/dailyOutfits/{date}`: `items` (itemId の list) + `image` (Storage の path) + `visibility` + `until` + `viewCount`
- Storage の path: 着姿 `users/{uid}/jobs/{jobId}/outfit.png`、切り抜き `users/{uid}/jobs/{jobId}/item-{n}.png` (vision が置いた物をそのまま指す。写さない)。自分の写真 `users/{uid}/photo.jpg`。着用イメージ `users/{uid}/tryons/{tryonId}.png`
- `blobs.py`: `get_blobs() -> Blobs` (lru_cache)。`Blobs.get(path) -> bytes | None`、`Blobs.put(path, data, content_type)`、`Blobs.delete(path)`。テストは conftest の `blobs` fixture (辞書の偽物を依存に差し込む)
- `cards.py`: `load_card(db, card_id, viewer_uid, now) -> dict`。無い・見る人が違う → 404 `not_found`、期限切れ → 410 `card_expired`。返すのは cards の文書 (`owner` `viewer` `outfitRef` `expiresAt` `items` {cardItemId: itemId})
- `auth.acting_uid(user) -> str`: 匿名 (Web デモの審査員) なら環境変数 `DEMO_VIEWER_UID`、そうでなければ自分の uid。照合と着用イメージで「誰の手持ちと写真を使うか」に使う。回数は本人の uid で数える

## Review Focus

- 期限の切れたカード・他人のカードで照合や画像を引く → 410 / 404 で、中身を返さない
- Gemini が渡していない itemId を返す → 捨てる (返した id が渡した一覧に在るかを確かめる)
- 処理の終わっていない jobId・他人の jobId で登録する → 409 `not_ready` / 404
- 匿名の利用者が DEMO_VIEWER_UID の無い環境で照合する → 403 で落とす (500 にしない)
- AI を止めた時 (`AI_DISABLED=1`) に事前の結果が無い → 503 `ai_disabled`

**Files:** Create `server/api/blobs.py`、`server/api/outfits.py`、`server/api/test_outfits.py`。Modify `server/api/conftest.py` (blobs の fixture)、`server/api/auth.py` (`acting_uid`)、`server/api/main.py` (router)、`server/api/Dockerfile`

- [ ] PUT `/v1/outfits/today`: jobs が `succeeded` でなければ 409 `not_ready`。選んだ index ごとに wardrobeItems を作り、dailyOutfits/{今日} に `items` と `image` を書く (既にある visibility・viewCount は残す)。TodayOutfit を返す
- [ ] GET `/v1/outfits/today` (無ければ 404 `not_found`)、`/v1/outfits/today/image`、`/v1/jobs/{jobId}/images/{name}` (`outfit` か `item-<n>` だけ)、GET `/v1/wardrobe` (`slot` で絞る)、DELETE `/v1/wardrobe/{itemId}`、`/v1/wardrobe/{itemId}/image`

### Task 2: 見る側の画像・ブロック・通報・模擬の検出

**Files:** Create `server/api/cards.py`、`server/api/test_cards.py`。Modify `server/api/nearby.py` (カードを作る部分を関数にして模擬の検出と共有)

- [ ] `load_card`、GET `/v1/cards/{cardId}/image` と `/items/{cardItemId}/image` (透かし: cardId の先頭 8 文字を薄く敷き詰める)、POST `/v1/blocks` (`blocks/{viewer}_{owner}`)、POST `/v1/reports`
- [ ] POST `/v1/demo/nearby`: 匿名の利用者だけ。DEMO_UIDS の人のカードを作って返す (お互いさまと 1 日 1 回は見ない)
- [ ] POST `/v1/admin/demo/reset`: `X-Admin-Token` を `ADMIN_TOKEN` と `hmac.compare_digest` で比べ、DEMO_UIDS が見られた viewLog を消す。ponytail: viewLog は HMAC なので、デモの人を見た記録だけを選べない。DEMO_UIDS は viewLog を書かない作りなので、消す物は無く 204 を返すだけでよいかを先に確かめる

### Task 3: 照合 (S3)・着用イメージ (S4)・AI を止める切り替え (S6)

**Files:** Create `server/api/match.py`、`server/api/tryon.py`、`server/api/ai.py`、`server/api/test_match.py`、`server/api/test_tryon.py`。Modify `server/api/main.py`、`server/api/requirements.txt` (`google-genai==3.0.*`、`pillow==12.*`)、`server/api/Dockerfile`

**Interfaces:**
- Consumes: Task 1 の `blobs`・wardrobeItems の形・`acting_uid`、Task 2 の `load_card`
- Produces: `ai.py` の `ask_match(seen: dict, seen_png: bytes, candidates: list[tuple[str, dict, bytes]]) -> dict` と `make_tryon(photo: bytes, garments: list[bytes]) -> bytes`。どちらも `AI_DISABLED=1` なら `AiDisabled` を投げる。テストは偽物に替える

- [ ] POST `/v1/match`: カードの服 1 着と、組み合わせる側の区分の手持ち (`acting_uid` の物、30 着まで) を `ask_match` に渡す。返った id が渡した一覧に無い物は捨てる。MatchResult を返す。回数 `match`
- [ ] PUT/DELETE `/v1/me/photo`: `capturedWith` が `camera` でなければ 400。`users/{uid}/photo.jpg` に置き、`users/{uid}.hasPhoto` を立てる
- [ ] POST `/v1/tryon`: 写真が無ければ 409 `photo_required`。見た服 + 選んだ手持ち (3 着まで、`acting_uid` の物だけ) を `make_tryon` に渡し、`users/{uid}/tryons/{tryonId}.png` に置く。GET `/v1/tryon/{tryonId}/image` は本人だけ。回数 `tryon`
- [ ] S6: `AI_DISABLED=1` の時、照合と着用イメージは事前の結果 (`precomputed/match_{owner}_{itemId}`、`precomputed/tryon_{owner}_{itemId}` の文書、D3 が作る) を返し、`precomputed: true` を付ける。無ければ 503 `ai_disabled`。デモの人物には AI を止めていなくても事前の結果を返す (`regenerate: true` の時だけ作り直す)

## 実装後に決まったこと (2026-11-08)

- 事前の結果 (D3 はこの形で作る)。名前に見る人 (acting_uid) を入れるので、他人の手持ちで作った結果は返らない。返すのは、見た服がデモの人 (`DEMO_UIDS`) の物の時と `AI_DISABLED=1` の時
  - `precomputed/match_{見る人}_{owner}_{itemId}` = `{combos, missing, similarOwned}`
  - `precomputed/tryon_{見る人}_{owner}_{itemId}_{選んだ手持ちの id を並べ替えて _ でつないだ物}` = `{image: Storage の path}`
- デモの人物の環境変数 (api): `DEMO_UIDS` = 判定から外す見られる側 (Web の架空の人物 + 壇上の A)。`WEB_DEMO_UIDS` = Web の模擬の検出に出す人 (架空の人物だけ)。`DEMO_VIEWER_UID` = Web の審査員が成り代わる架空の見る人。壇上の B は本人のアカウントのまま
- 匿名の回数は全員で 1 つ (`quotas/anonymous_{日付}`、照合 100・着用イメージ 30、`QUOTA_ANON_<種類>` で変える)。vision は匿名を 403 にする
- カードは作った時の着姿の path と `demo` を持つ。持ち主が公開をやめたら (デモの人物を除く) 410。ブロックは両向き
- Gemini の失敗は 502 `internal`。想定外の失敗も Error の形の 500 で、ログには例外の型の名前だけ
- 着用イメージの PNG には下の帯に英字で「AI-generated」を焼き込む
