# vision の本体 (V3) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `POST /v1/outfits/process` を作る。全身写真を受け、頭を塗り、背景を消し、Gemini で服を見つけ、SAM 2.1 で切り抜き、Storage と Firestore の `jobs` に結果を書く。

**Architecture:** 処理は 1 本の関数 `process(img, gemini, sam, ...) -> JobResult` にまとめ、FastAPI の口はそれを呼んで Storage と `jobs` に書くだけにする。Gemini と SAM は引数で渡し、テストでは小さな偽物に差し替える (本物は手元の試験の台本で確かめる)。元の写真はメモリの中だけで扱い、どこにも保存しない。

**Tech Stack:** Python 3.12、FastAPI、google-genai (Agent Platform、`gemini-3.8-flash`、`response_schema`)、transformers の SAM 2.1 tiny、rembg (isnet)、OpenCV (YuNet)、firebase-admin (Firestore と Storage)、pytest

**Spec:** `docs/architecture.md` (3.1 の表、5 節)、`docs/api.yaml` (`/v1/outfits/process`、`Job`)、`docs/tech-decisions.md` (4)

## Global Constraints

- 頭は `masking.paint_head` で常に塗り、`masking.find_faces` で塗った後に顔が 1 つでも残っていたら止める (`jobs` に `failed` と `face_detected`)。その時は Gemini に送らない
- Gemini に送るのは、頭を塗り背景を消した画像だけ
- 元の写真は保存しない。ログにも書かない
- Gemini の出力は `response_schema` で形を決める (前に壊れた JSON が 1 回あった)。区分は `docs/api.yaml` の `Slot` の 7 つ
- SAM: どの服も、その服の点を「含める」、ほかの服の点を「除く」として渡す。画像の読み込み (`get_image_embeddings`) は Gemini の応答を待つ間に始める
- `jobs` の `status` は `queued → masking → segmenting → detecting → cutting → succeeded / failed` (`docs/api.yaml`)
- 書く場所: Storage `users/{uid}/jobs/{jobId}/outfit.png`、`.../item-{index}.png`。Firestore `users/{uid}/jobs/{jobId}`
- 認証: Firebase の ID トークン (api の `auth.current_user` と同じやり方)。回数の上限は 1 日 20 回

## Review Focus

- 人が写っていない写真・2 人以上が写っている写真: `no_person` で止まるか、主な 1 人 (一番大きい塊) で進むか
- Gemini が服を 0 着で返した時: `succeeded` で `items: []` になり、画面が「服が見つかりません」を出せること
- Gemini が画像の外の点や枠 (1000 を超える値) を返した時: 落ちずに切り詰めること
- 縦横の大きい写真 (長辺 4000px): 長辺 2048px に縮めてから処理すること
- 同時に 2 枚: 顔の検出器の取り違えが無いこと (`masking` の鍵で守られている)
